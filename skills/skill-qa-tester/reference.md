# 技能质量测试 — 详细参考

## 一、核验规则详解

### 1.1 数据准确性核验

#### 标准编号核验

核验标准编号时，需同时检查四个维度：

| 维度 | 正确示例 | 错误示例 | 核验方法 |
|------|---------|---------|---------|
| 前缀 | GB/T 23445 | GBT 23445, GB-T 23445 | 对照源文件 |
| 年份 | -2025 | -2024 | 对照源文件+官方状态 |
| 名称 | 聚合物水泥防水涂料 | 聚合物水泥防水材料 | 逐字比对 |
| 状态 | 🟢现行/🟡即将实施/🔴已废止 | 状态与日期矛盾 | 对照实施日期 |

#### 数值核验

- **精确匹配**：数值必须与源文件完全一致，包括小数位数
- **单位一致**：dB/mm/h 等单位必须与源文件一致
- **精度一致**：源文件写"≥1.5mm"不能变成"≥1.50mm"
- **范围表达**：源文件写"45~50"不能变成"45-50"

#### 边界符号核验

| 标准原文表述 | 对应符号 | 常见错误 |
|------------|---------|---------|
| 不应小于 | ≥ | 误用 > |
| 不应大于 | ≤ | 误用 < |
| 大于 | > | 误用 ≥ |
| 不应低于 | ≥ | 误用 > |

核验方法：在源文件中搜索"不应小于""大于"等关键词，确认对应的数学符号。

### 1.2 格式合规性核验

#### 输出模板核验

对照 SKILL.md 中定义的模板结构，逐项检查：
- 模板中所有必填章节是否都已出现
- 章节标题文字是否与模板定义一致
- 章节顺序是否与模板定义一致
- 数据标注（标准数据/产品数据/经验数据）是否正确
- **分类口径**：数据分类与取证判据见 `shared/data-classification.md`；核验数据标注时先判类别再取判据，B／C／D 类不因渠道标注等级低而判错（效力关系见其 §四.2）。

#### 响应层级核验（如技能定义了分层响应）

| 层级 | 触发条件 | 响应方式 | 核验要点 |
|------|---------|---------|---------|
| Layer 1 | 规范有明确规定 | 直接给结论 | 是否引用了条款出处 |
| Layer 2 | 条件明确的常规场景 | 给出清晰方向 | 是否未过度教学 |
| Layer 3 | 条件复杂/模糊 | 引导分析 | 追问是否简洁（2-3个问题） |

### 1.3 红线合规性核验

#### 数据编造检测

对比模拟响应中的每个具体数值，确认它能在源文件中找到对应：
- 源文件有该数值 → 通过
- 源文件无该数值但响应标注了"约""一般" → 警告（需评估是否合理）
- 源文件无该数值且响应给出精确数值 → 不通过（疑似编造）

#### 品牌推荐检测

扫描模拟响应中是否出现具体品牌名称。以下情况需注意：
- 直接推荐品牌 → 不通过
- 举例提及品牌（如"类似XX品牌的产品"）→ 视技能定义判断
- 提及检测机构/标准组织名称 → 正常（非品牌推荐）

### 1.4 内部一致性核验

#### 跨文件一致性检查矩阵

对技能中所有涉及同一主题的内容，建立交叉比对矩阵：

```
检查项：GB 55030-2022 的引用

SKILL.md        → 第X行：[内容]
reference.md    → 第Y行：[内容]
examples.md     → 第Z行：[内容]
thinking.md     → 第W行：[内容]

一致性判定：
- 标准编号：全部一致 / 第N处不一致
- 年份：全部一致 / 第N处不一致
- 名称：全部一致 / 第N处不一致
```

#### 免责提示文本一致性

1. 以 SKILL.md 中定义的免责提示文本为基准
2. 在所有文件中搜索免责提示出现的位置
3. 逐句比对每个位置与基准文本的差异
4. 任何差异（包括标点符号）均记录为不一致

#### 示例文件与主表格一致性

1. 提取主表格中的所有关键数值
2. 在示例文件中搜索对应数值
3. 确认数值、指标类型、标准引用一致
4. 特别注意：示例可能使用不同场景（如不同建筑类型），数值可能合理地不同于主表格——需判断是"不一致"还是"不同场景的合理差异"

## 二、时效性检查方法

### 2.1 标准状态时效性

对每个标准执行以下检查：

```
标准编号：[XXXX]
实施日期：[YYYY-MM-DD]
当前日期：[今日]
状态标记：[源文件中标记]

判断逻辑：
- 实施日期 ≤ 当前日期 → 应为"🟢现行"或"已实施"
- 实施日期 > 当前日期 → 应为"🟡即将实施"
- 已被替代 → 应为"🔴已废止"
```

### 2.2 数量统计一致性

当源文件中声明了数量（如"收录55项标准"）时：
1. 实际计数：逐条计数对应内容
2. 对比声明数量与实际数量
3. 注意子条目（如序号44-1）的计数方式
4. 如数量不一致，检查是否有新增/删除未同步更新

## 三、对抗性测试用例库

### 3.1 通用对抗性测试

以下测试适用于大多数知识密集型技能：

**测试A：信息不足诱导**
- 查询：故意缺少关键条件的问题
- 预期：技能应追问或声明条件不足，而非凭空回答
- 核验：响应中是否有"需要了解X信息""条件不明确"等表述

**测试B：错误前提纠正**
- 查询：包含错误假设的问题（如"GB 55038-2024已经废止了吧？"）
- 预期：技能应纠正错误前提
- 核验：响应中是否指出了前提错误并给出正确信息

**测试C：跨领域越界**
- 查询：超出技能范围的问题
- 预期：技能应识别越界并路由到正确技能
- 核验：是否触发了跨技能路由规则

**测试D：精确数据诱导**
- 查询：要求给出"精确到小数点后两位"的数值
- 预期：如果源文件没有该精度的数据，应诚实说明
- 核验：是否编造了超出源文件精度的数值

### 3.2 数据表格型技能专项对抗

**测试E：表格外查询**
- 查询：询问表格中未列出的项目
- 预期：应说明"未收录"而非编造数据

**测试F：单位混淆诱导**
- 查询：使用与源文件不同的单位（如问"多少英寸"而源文件用mm）
- 预期：应使用源文件的单位，或明确标注换算来源

### 3.3 方法论型技能专项对抗

**测试G：结论倒推**
- 查询：给出结论要求反推过程
- 预期：推理过程应与源文件中的方法论一致

**测试H：方法论误用**
- 查询：场景明显不适合该方法论
- 预期：应识别适用范围限制

### 3.4 审核工具型技能专项对抗

**测试I：无误文本测试**
- 输入：一段完全正确的文本
- 预期：应报告"未发现问题"，不应误报

**测试J：隐蔽错误测试**
- 输入：错误藏在细节中（如第5行的年份错误）
- 预期：应检出所有错误，不应因位置隐蔽而遗漏

## 四、打包检查清单

### 4.1 打包前检查

```
- [ ] 所有技能定义文件完整（SKILL.md + 参考文件）
- [ ] 无残留临时文件（.tmp, .bak, nul 等）
- [ ] 无运行时文件（node_modules, .git, .env, .next 等）
- [ ] 无数据库文件（*.db, *.sqlite 等）
- [ ] 文件引用路径正确（SKILL.md 中引用的文件名与实际文件名一致）
- [ ] 所有文件非空（SKILL.md 至少有 frontmatter）
```

### 4.2 打包后验证

```
- [ ] .skill 文件大小合理（与源文件总大小匹配）
- [ ] 包内文件数量正确
- [ ] 包内文件名和大小与源文件一致
- [ ] 功能冒烟测试通过（加载+基础响应）
```

### 4.3 Windows 环境打包注意事项

PowerShell `Compress-Archive` 不支持 .skill 扩展名，需先打包为 .zip 再重命名：

```powershell
Compress-Archive -Path '.\SKILL.md','.\reference.md','.\examples.md' -DestinationPath 'output.zip' -Force
# 然后 mv output.zip output.skill
```

Linux/macOS 可直接使用 zip 命令：

```bash
zip skill-name.skill SKILL.md reference.md examples.md
```

## 五、测试报告质量自检

生成测试报告后，自检以下项目：

| 自检项 | 标准 |
|--------|------|
| 覆盖完整性 | 所有输出模板和响应层级均有对应用例 |
| 核验粒度 | 每个核验项有明确的"依据"（文件+行号） |
| 问题分类 | 严格区分"错误"（必须修复）和"警告"（建议改进） |
| 修正记录 | 每个修正有"修正前/后/依据"三要素 |
| 回归确认 | 修正后重新执行受影响用例 + 完整性扫描 |
| 改进闭环 | 改进建议已处理或明确标注"待处理" |
| 统计准确 | 通过/不通过/警告的计数正确 |

## 六、回归验证操作规程

### 6.1 修正后完整性扫描（必做步骤）

每次用 Edit 工具完成修正后，**在报告"已修复"之前**，必须执行以下扫描流程：

#### 步骤一：确定扫描范围

根据修正的类型，确定需要扫描的范围：

| 修正类型 | 扫描范围 | 示例 |
|---------|---------|------|
| 表格中某些行的格式/数值 | 该表格的**全部行** | Section 9状态表修了5行→扫描全部8行 |
| 某文件中多处出现的文本 | 该文件的**全文** | 免责声明修了4处→搜索全文确认无第5处 |
| 某个标准编号/数值变更 | **所有文件**中该编号/数值的出现位置 | GB 45671状态变更→搜索全部6个文件 |
| 状态标识系统统一 | 使用该标识系统的**所有章节** | 🟢/🟡/🔴系统→检查Section 2-9所有章节 |

#### 步骤二：执行全量扫描

**方法A — 全表读取法**（适用于表格修复）：
1. 用 Read 读取修复后表格的全部行（从表头到最后一行）
2. 逐行检查是否都符合修正后的规则
3. 记录每行的检查结果（通过/不通过）

**方法B — Grep全文搜索法**（适用于文本/模式修复）：
1. 用 Grep 搜索旧模式关键词 → 预期结果：0匹配
2. 用 Grep 搜索新模式关键词 → 预期结果：匹配数 = 原旧模式出现次数
3. 如果旧模式仍有匹配，说明存在遗漏

**方法C — 跨文件搜索法**（适用于数据变更）：
1. 用 Grep 在技能目录下搜索被修改的标准编号/数值
2. 逐处确认每处引用是否需要同步更新
3. 如需更新则立即修复，修复后再次扫描确认

#### 步骤三：计数比对

修正前后做计数比对，确保覆盖完整：

```
修正前：旧模式出现 N 次
修正后：新模式出现 M 次，旧模式残留 R 次
验证：M + R = N（总数不变），且 R = 0（无残留）
```

### 6.2 回归失败案例库

以下为实践中遇到的典型回归失败案例，作为后续测试的参照：

#### 案例1：表格部分修复遗漏

- **场景**：某索引文件Section 9共8行数据，其中5行使用纯文本状态（"2025版已发布""已实施"），与Section 1定义的🟢/🟡/🔴/⚪状态标识系统不一致
- **修复**：将5行纯文本状态统一为emoji标识
- **遗漏**：Section 9剩余3行也使用纯文本（"正在修订""关注修订动态"），但未被修复
- **根因**：修复时只针对了"已知有问题"的5行，没有对全表8行执行一致性扫描
- **检测**：修复后如果读取Section 9全部8行逐行检查，可以立即发现3行遗漏
- **教训**：修复表格中某些行时，必须读取全表逐行验证

#### 案例2：免责文本跨文件不一致

- **场景**：SKILL.md定义了标准免责提示文本，但examples.md中4处免责声明各自不同，且都缺少SKILL.md中的某些句子
- **修复**：4处统一替换为SKILL.md标准文本
- **检测方法**：修复后用 Grep 搜索"本回复基于"确认4处全部匹配，搜索"免责声明"确认旧前缀已全部清除
- **教训**：批量替换后用 Grep 双向搜索（新模式+旧模式）确认无遗漏

#### 案例3：状态标识系统跨章节不一致

- **场景**：某索引文件Section 2-7使用🟢/🟡/🔴标识，但Section 9使用纯文本
- **根因**：Section 9是后期添加的"更新预警"表，编写时未遵循Section 1定义的状态标识规范
- **检测**：用 Grep 搜索🟢/🟡/🔴，统计每个Section的出现次数，发现Section 9为0
- **教训**：当同一文件定义了全局格式规则时，修正后需逐章节检查执行情况

### 6.3 回归验证检查清单

每次修正后，在完成回归测试之前，逐项勾选：

```
□ 修正的表格/章节已全量读取并逐行检查
□ 旧模式在全文的 Grep 搜索结果为 0 匹配
□ 新模式的出现次数与预期一致
□ 跨文件中引用同一数据的位置已逐处确认
□ 相邻行/相邻段落无同类遗漏
□ 修正前后的计数比对已完成（M + R = N, R = 0）
□ 回归测试覆盖了修复行所在的完整结构（表格/章节/列表）
```

只有全部勾选后，才能将该修正标记为"已修复"并进入下一环节。
