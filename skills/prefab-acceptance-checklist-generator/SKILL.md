## 1. 角色定位

本技能是**验收清单转化器**，将各专项技能（墙面/吊顶/地面/厨卫/收纳/机电）的技术输出转化为：

- **可检查**：每个检查项有明确的合格标准和检验方法
- **可记录**：每个检查项有记录栏，支持现场填写
- **可整改闭环**：不合格项有整改跟踪机制

**边界声明**：本技能不制定验收标准（标准来自国家/行业规范），不替代监理/质检人员的现场判定，仅提供结构化清单工具。验收判定须由具备相应资格的人员（监理工程师/质量检查员）执行。

### 1.1 作答协议（CG-20261019-015 推广，欠定问法适用）

当题面只给"出个清单/必检哪些"而未给优先维度时，按三步作答：① **列决策变量**——验收阶段/空间与部品范围/必检项覆盖/抽检比例/资料完备/整改闭环/工期，并注明题面已给与缺失的维度；② **每维给口径与档位**——合格标准标明"规范规定值/设计值/本合集加严值/须第三方检测"，缺数据的条目写"以设计文件为准"，不得编造条款号；③ **给条件式结论**——先给默认清单范围与深度，再写"若验收阶段/合同要求改为 X 则增列 Y"。示例与翻选条件见 reference.md §9。

### 2.2 清单生成规则

每个检查项**必须**包含以下要素：

| 要素 | 说明 | 示例 |
|---|---|---|
| 检查项目 | 具体检查对象/内容 | 轻钢龙骨间距 |
| 合格标准 | 量化的合格判定条件 | 间距偏差≤3mm |
| 检验方法 | 具体检测手段 | 钢尺量测 |
| 依据来源 | 标准条款或设计文件 | GB 50210-2018 第7.2.4条 |
| 记录栏 | 现场填写实测值/结果 | （空白，现场填写） |
| 判定 | 五态：合格/带条件合格/不合格/无法判定/不适用（定义见 §2.2.1） | （空白，现场判定） |

**生成原则**：
- 合格标准必须量化或可明确判定（避免"符合要求"等模糊表述）
- 检验方法必须可操作（避免"观察"作为唯一方法，应配合量具）
- 依据来源必须标注具体标准编号和条款号，或标注"设计文件"
- 不编造标准条款号——不确定时标注"参见相关标准，具体条款以设计文件为准"

#### 2.2.1 判定五态（现场判定栏取值）

| 判定 | 含义 | 处置要求 |
|---|---|---|
| **合格** | 合格标准满足，且证据齐全可核 | 进入下一工序/阶段 |
| **带条件合格** | 主控项满足；仅一般项单点超差但未超 reference.md §7 规定的最大偏差限值、检验批一般项目抽样合格率满足 §7；未构成 reference.md §4.2 任一级不合格、非必检项；有可控整改项 | 必须列整改项、复验条件、责任方；不得只写"基本合格" |
| **不合格** | 明确不满足合格标准（超出 reference.md §7 判定上限、构成 §4.2 任一级不合格，或主控项不满足、影响安全或主要功能） | 按 reference.md §4.1 整改闭环执行，不得以"无法判定"替代 |
| **无法判定** | 检查项适用，但证据缺失、现场条件不具备，或标准版本冲突且无法按 §4 仲裁规则裁定，当前无法得出结论 | 单列，不计入清单项判定合格率；必须写缺失证据、补证责任方、复验条件；不得按合格放行 |
| **不适用** | 本项目/本部位/本阶段不存在该检查对象 | 必须写明不适用依据（设计无此部位、本阶段不涉及）；不得用不适用规避检查 |

**判定顺序**（自上而下，先命中先定）：

1. **不适用** → 本项目/本部位/本阶段不存在该检查对象，且有不适用依据。
2. **未检查** → 应检查而尚未检查：判定栏留空，单列"未检查"计数（不属于五态）。
3. **无法判定** → 对象存在，但证据缺失、现场条件不具备，或标准版本冲突且无法按 §4 仲裁规则裁定。
4. **不合格** → 明确不满足合格标准（限于主控项不满足、影响安全或主要功能、按 reference.md §4.2 构成任一级不合格，或超出 reference.md §7 表规定的最大偏差限值或一般项目合格率要求）。
5. **带条件合格** → 仅一般项单点超差但未超 reference.md §7 表规定的最大偏差限值、检验批一般项目抽样合格率满足 §7；不影响安全与主要功能、未构成 reference.md §4.2 任一级不合格、非必检项；并有可控整改项与复验条件。
6. **合格** → 全部满足且证据齐全。

**判定纪律**：

1. **无法判定与不合格不得互换**——缺证据判"无法判定"，有证据证明不满足判"不合格"；质量不合格不得降格为"无法判定"，缺证据也不得升格为"不合格"。
2. **无法判定不计入合格率**——清单项判定合格率分母＝合格＋带条件合格＋不合格，不含无法判定、不适用与未检查；带条件合格单列，不并入合格。
3. **判定不得跨阶段继承**——任一阶段判定均须按该阶段证据重新作出；隐蔽阶段判为无法判定的，竣工阶段须重新取证判定，不得自动转为合格。
4. **判定栏不得预填**——未现场检查的项一律留空，不得默认"合格"。
5. **不适用须逐项有依据**——无法确定是否适用时，判"无法判定"而非"不适用"。
6. **强制性条文/必检项不得判"带条件合格"**——只能判合格、不合格、无法判定或不适用，不得用条件式状态软化必检项刚性。

#### 2.2.2 证据状态（与依据来源并列，但不是同一轴）

| 证据状态 | 含义 |
|---|---|
| **已具备** | 现场已取得可直接核对的证据（实测记录、报告、隐蔽影像、签认单） |
| **部分具备** | 仅有非判据性辅助证据（如部分影像、旁证记录），判据性证据尚未取得 |
| **缺失** | 应具备的证据尚未取得 |
| **待现场复核** | 需现场复测/开孔/通水/闭水后才能取得 |

证据状态**不是** S1/S2/S3 的替代：S1/S2/S3 说明"依据来自哪类渠道"（见 §3 Step 4 与 `shared/data-classification.md` §四），证据状态说明"这一条当前能不能判"。两者分别填写，不得互相顶替。

证据状态用于判定推理与专项表填写，**不单独占用主表列**；主表只保留判定五态。

四档取一，按以下优先级：需现场取得 → "待现场复核"；应取得而未取得 → "缺失"；有证据但覆盖不全 → "部分具备"；已取得且可核对 → "已具备"。

## 3. 工作流程

### Step 0：确认验收范围

- 确认四项入参：项目类型、验收阶段、空间范围、部品系统范围（取值枚举单源＝`../shared/interface-contracts.md` IC-14「请求参数约束」表，本件 §9 逐参数指回该表；本件不复制枚举值）
- 信息不足时，列出需确认项，不做假设

### Step 1：识别部品系统

- 根据项目信息确定涉及的部品系统
- 调用对应专项技能获取技术要求
- 列出各系统的验收子项

### Step 2：匹配验收标准（IC-10/SRE 集成）

- 调用 IC-10（标准推理引擎），按 §11.1 字段表传入 IC-10 请求五字段（项目类型、空间类型、项目所在地、构造体系、性能需求），获取适用标准集与推理路径
- 以 SRE 返回的适用标准集为基准，为每个检查项匹配对应标准条款
- 标注数据来源级别（S1/S2/S3）
- 不确定的标注"参见相关标准，具体以设计文件为准"
- 涉及强制性条文的标记为必检项
- **SRE 不可用时降级**：使用本技能 §8 参考标准表 + §2.4 强制性条文检查项执行标准匹配，在清单头部标注"SRE 降级：使用 ACG 内置标准映射，标准集未经场景推理筛选"

### Step 3：生成检查条目

- 按清单生成规则逐项编制
- 确保每项包含：检查项目/合格标准/检验方法/依据来源/记录栏
- 按施工顺序或空间顺序排列
- 必检项置顶或加粗标注

### Step 4：标注来源与分级

- 每条依据标注S1/S2/S3级别
- S1：直接引用标准条款号
- S2：标注"行业通用做法"或"设计文件"
- S3：标注"经验数据，具体以设计文件为准"
- 不编造条款号
- **分类口径**：数据分类与取证判据见 `shared/data-classification.md`；本步骤 S／L 等级仅为该文件 §四.1 的渠道／标注轴，对 B／C／D 类数据作信息性标注、不构成 pass/fail 判据（效力关系见该文件 §四.2）。

### Step 5：输出清单

- 按输出模板格式化
- 附整改闭环表
- **附「无法判定与带条件合格专项表」**：逐项列缺失证据/整改项、责任方（补证/整改）、复验条件、计划复验时间
- **输出判定统计**：五态计数＋未检查计数；清单项判定合格率分母不含无法判定、不适用与未检查
- 附标准免责提示
- 提示需专业资格人员判定的项目
- 需要可编辑成果时，按 §5.1 用 `scripts/export_checklist.py` 导出 XLSX 与 DOCX；导出件与清单同源，不另造数据

## 4. 红线体系

以下 13 条红线已注册于红线注册表§十六（全局编号 AC-R-*），完整定义以 `../shared/redlines-registry.md` 为准。

### P0 红线（违反即清单不合格，必须整改）

- **AC-R-P0-1 严禁遗漏强制性条文检查项**：第2.4节所列必检项在任何相关清单中不得缺失
- **AC-R-P0-2 严禁编造验收标准**：不得虚构标准条款号、不得编造不存在的指标值
- **AC-R-P0-3 严禁强制项与一般项级别混淆**：不得将非强制项标注为强制项，或将强制项降级为一般项
- **AC-R-P0-4 严禁遗漏隐蔽工程验收节点**：凡被下道工序覆盖的检查项必须列入隐蔽验收

### P1 红线（重要缺陷，应整改）

- AC-R-P1-1 合格标准未量化（仅写"符合要求"）
- AC-R-P1-2 检验方法不可操作（仅写"观察"无量具）
- AC-R-P1-3 依据来源缺失（无标准编号或"设计文件"标注）
- AC-R-P1-4 检查项覆盖不完整（遗漏部品系统关键检查项）
- **AC-R-P1-5 严禁跳过 SRE 标准推理**：Step 2 必须调用 IC-10（标准推理引擎）获取场景化适用标准集；SRE 不可用时须执行 §11.3 降级流程并在清单头部标注降级标记，不得静默跳过

### P2 红线（一般缺陷，宜优化）

- AC-R-P2-1 检查项排序不合理（未按施工顺序）
- AC-R-P2-2 记录栏格式不统一
- AC-R-P2-3 缺少整改闭环跟踪表
- AC-R-P2-4 缺少现场照片记录提示

### 红线冲突仲裁规则

当清单生成遇到标准冲突或信息矛盾时：
1. 强制性条文 ＞ 推荐性标准 ＞ 行业惯例 ＞ 经验数据
2. 新版本标准 ＞ 旧版本标准（以现行有效版本为准）
3. 设计文件指标严于标准时，按设计文件
4. 无法判定时，按 §2.2.1 判"无法判定"，注明缺失证据与补证路径，并提示由监理工程师或设计方明确；不得用"合格""不合格""不适用"任一项替代
5. 仲裁结果须在清单备注中说明

### 5.1 导出为可编辑成果（XLSX＋DOCX）

需要把清单直接交给同事续填、审批或归档时，把按 §5 模板填好的 Markdown 交给 `scripts/export_checklist.py`：

```
python scripts/export_checklist.py <清单.md> [--out <目录>] [--stem <文件名>] [--force]
```

- **产出**：同名 `.xlsx` 与 `.docx`。XLSX 含 8 个工作表——封面与依据、检查表、无法判定与带条件合格专项表、强制性条文检查项、整改闭环表、判定统计、未决事项、资料归档清单；检查表、必检表、专项表、整改闭环表与归档表带筛选/冻结或下拉取值（判定五态、证据状态、是否具备）。
- **不丢项**：导出件必须保留编制依据、适用条件、假设与限制、编制版本、未决事项；缺编制依据、编制版本、假设与限制或对应章节即拒绝导出（退出码 2，不产出半成品）并逐条列出缺项。未决事项表须存在，可为空表（表示无未决事项）。
- **不覆盖**：默认拒绝覆盖已存在的同名 `.xlsx`/`.docx`；确认覆盖须显式加 `--force`。
- **可追溯**：封面与 DOCX 首段写入编制版本、生成时间、输入文件名与完整 SHA-256；DOCX 为方案摘要，逐条检查项以 XLSX 为准。
- **边界**：导出件是清单的镜像与摘要，不替代监理工程师/质量检查员的现场判定；判定栏由具备相应资格人员填写。
- **依赖**：只用 Python 标准库（3.10+），不联网、不装第三方包。脚本缺失或运行失败时，按 §5 模板交付 Markdown 并说明未生成 Office 文件，不得伪造 `.xlsx`/`.docx` 或声称已导出。

| 生成结构化验收清单 | 替代现场验收判定 |
| 匹配标准条款 | 出具验收报告/签章 |
| 标注检验方法 | 确定具体验收指标（须来自设计文件） |
| 生成整改闭环表 | 判定整改方案是否合格 |
| 提示必检项 | 替代监理职责 |
| 列出资料归档清单 | 确认资料真实性 |
| 区分合格／带条件合格／不合格／无法判定／不适用，并列出补证路径 | 替代具备资格人员作最终验收结论 |

**凡涉及验收判定、质量等级评定，必须由具备相应资格的监理工程师或质量检查员执行。**

## 9. 接口契约（IC-14 接收方）

**请求参数**（与 IC-14-Request Schema 字段集一致，Schema 为 additionalProperties:false）：

| 参数 | 必填 | 说明 |
|------|------|------|
| 项目类型 | 是 | Step 0 收集；取值枚举单源＝`../shared/interface-contracts.md` IC-14「项目类型」行（含"未提供"态及其输出降低确定性语义） |

| 空间范围 | 是 | Step 0 收集；取值枚举单源＝`../shared/interface-contracts.md` IC-14「空间范围」行，缺失时按契约追问、不做假设 |

## 11. IC-10 标准推理引擎集成调用

本技能在 Step 2（匹配验收标准）中集成调用 IC-10（标准推理引擎），实现标准匹配从静态查表到场景推理的升级。

### 11.1 调用时机与参数

| 项目 | 说明 |
|------|------|
| **触发时机** | Step 2 开始时，确认部品系统范围后 |
| **调用方向** | ACG → prefab-standards-reviewer（SRE） |
| **契约编号** | IC-10（完整定义见 `../shared/interface-contracts.md` §4.4） |

**请求参数**（与 IC-10 请求参数约束表一致，见 `../shared/interface-contracts.md` 本契约"请求参数约束"表）：

| 参数 | 必填 | 本技能填充来源 |
|------|------|--------------|
| 项目类型 | 是 | Step 0 收集；取值枚举单源＝../shared/interface-contracts.md IC-10「项目类型」行；缺失时按契约返回"参数不足"，回到 Step 0 补齐后再调用 |
| 空间类型 | 是 | Step 0/Step 1 的验收对象空间（自由文本：分户墙/客房隔墙/走廊隔墙/卫生间/厨卫湿区/楼地面/吊顶等；卫生间、厨房等由 SRE 归一化到「厨卫湿区」空间维度） |
| 项目所在地 | 否 | Step 0 收集；缺失时 SRE 默认"全国"并在清单标注 [AC-R-P1-3]（未筛选地方标准） |
| 构造体系 | 否 | Step 1 上游专项技能方案结论（轻钢龙骨/条板/模块化/浮筑地面等）；缺失时 SRE 返回全构造体系适用标准 |
| 性能需求 | 否 | Step 0/Step 1 部品系统＋验收阶段映射（数组，验收场景含"验收"，可附隔声/耐火/环保等细分需求）；缺失时由 SRE 按「按规范」默认推理 |

> 以"标准编号＋条文号"为入参的条文级核验走 IC-07（见 §11.4），不走 IC-10。

### 11.2 响应使用

SRE 返回的**适用标准集**作为 Step 2~5 的合规基准：

- **适用标准集**：按此筛选 §8 参考标准和 §2.4 必检项中的适用条目，排除不适用的标准
- **标准状态**：废止/替代的标准触发 AC-R-P0-2 防护——不得将已废止标准作为验收依据
- **推理路径**：记录推理链路，在清单备注中引用，便于追溯标准选择依据

### 11.3 SRE 不可用降级

当 SRE 不可用时（接口超时、技能未安装等），按 `../shared/interface-contracts.md` §6.1 IC-10 降级策略执行：

1. 使用本技能 §8 参考标准表 + §2.4 强制性条文检查项执行标准匹配
2. 在清单头部标注："SRE 降级：使用 ACG 内置标准映射，标准集未经场景推理筛选"
3. 所有 S1 级标准标注降级为"S1（内置映射，未经 SRE 场景推理验证）"
4. 建议用户在 SRE 恢复后重新生成清单以获得场景化标准筛选

### 11.4 与 SR（IC-07）的分工

- **IC-10（SRE）**：场景化标准集筛选——"这个项目/场景适用哪些标准"
- **IC-07（SR）**：条款级精确核验——"这个具体条款号是否存在、版本是否现行"
- Step 2 优先使用 IC-10 获取标准集；当需要逐条核验条款号准确性时，路由至 `prefab-standards-reviewer`（IC-07）
