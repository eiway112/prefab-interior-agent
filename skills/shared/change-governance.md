# 装配式装修技能合集 — 知识变更治理规则

> **文件定位**：合集级共享资源，定义技能合集中所有共享知识（标准、术语、接口、红线）的变更管理流程。路径：`shared/change-governance.md`
>
> **维护规则**：本文件的修改须按 §二 第 3 步的**承担者取法**复核（本文件自身条款属「治理判据面」，其承担者＝该面常驻机算守卫全绿＋独立复核，不点名 prefab-standards-reviewer——该技能射程不含治理条款，理由与边界见 §二 第 3 步注），并记录在变更日志中。
>
> **公开分发面边界**：本件在公开派生面只含治理规则本体；变更日志「变更日志」与 §11.2「遗留台账」属开发仓登记面，派生时整节裁除、不随公开面分发。下文凡称「变更日志」「遗留台账」「变更日志」「§11.2」者均指开发仓对应节，本仓内无可直接打开的对应表。
>

>
> **适用范围**：standards-index.md、glossary.md、interface-contracts.md、redlines-registry.md、standards-reasoning-rules.md，以及各子技能 SKILL.md / reference.md 中与共享资源存在引用关系的内容。

## 一、变更分类

所有知识变更按影响范围和紧急程度分为四个级别。

| 变更级别 | 定义 | 典型场景 | 响应时限 |
|---------|------|---------|---------|
| **S 级 — 安全紧急** | 涉及人身安全、标准强制性条文废止或更正，不立即处理可能导致技能输出违反现行法规 | 强制性国标废止/更正、安全红线触发逻辑错误 | **24 小时内**完成影响评估并发布修复 |
| **A 级 — 标准废止** | 推荐性标准或行业标准被废止/替代，技能引用了已失效的条文 | 推荐性国标废止、产品标准被新版替代、地标更新 | **7 日内**完成影响评估和更新 |
| **B 级 — 常规更新** | 新增内容、修正错误、优化表述等不影响安全性的常规变更 | 新增标准收录、术语定义修正、接口参数调整、红线补充 | **当前开发阶段内**完成 |
| **C 级 — 优化调整** | 文档结构优化、措辞改善、格式统一等不影响功能和准确性的变更 | 排版统一、章节重组、说明文字润色 | **按排期处理**，不阻塞当前工作 |

## 二、变更审批流程

所有 B 级及以上的变更须遵循以下四步流程。C 级变更可由变更发起人直接执行，但须记录变更日志。

> **治理冻结令（阶段 0 转向，CG-20261019-007，发起人 2026-10-19 面板裁定＝"采纳冻结令（推荐）"）**：本仓 2026-10-19 采纳第三方独立审计报告（`成果/第三方独立审计报告_20261019_谋专思三段.md`）§二 谋-1／谋-2／§五 阶段 0-3 之建议，进入**治理维持模式**。以下条款叠在四步流程之上，与既有判据并跑：
>
> 1. **北极星指标**＝**人类评审下的真实场景可用率**（同句已写入 AGENTS.md 项目定位节；该节是本条的常驻可读面）。治理面处于维持模式，只为该标准服务。
> 2. **冻结面**＝在本令解除之前（解除条件**单源＝第 5 条**，该条自 CG-20261019-017 起不再以发起人另设数值阈值为前提），**不新增**门禁件、检查项、台账列与常驻机制。既有门禁与既有登记面照常跑、照常改，不属"新增"；§1.6 独立复核与既有门禁全绿仍照常承担，不因本令豁免。
> 3. **治理批插队须自证阻断面**＝每个治理批（含 C 级）须在同批登记载体（本件 变更日志 本批行级别格或执行记录）写明"它阻断了哪个内容批／哪一条现行判据"；未写者视为默认降级为**内容批之后**执行，不视为违规、只是不占先。既有先例（AGENTS.md 结构性外移 CG-20261019-003）即符合该判据（阻断＝本仓 19,999／20,000 B 临界态使下一批写不进判据载体）。
> 4. **提交面标签（一次性统计，不新建门禁）**＝每批 commit 标题自带 `内容`／`治理` 标签之一（**实测形制**＝`docs(CG-YYYYMMDD-NNN 治理): …`，标签与右括号之间一个空格、标签自身不带括号）；治理批占比按 `git log --since=<月首> --format='%s'` 之后接 `grep -c ' 治理)'` 现读，分母取同式 `grep -c ' 内容)'` 与 `grep -c ' 治理)'` 之和；实测到的第三枚标签 `发布闭环` **两不计入**（它与同 CG 编号的 `内容` 腿成对出现，计入分母即把同一批改两次）；按 §五 阶段 0-3 验收判据 ≤30% 观察，本仓**不为此新建任何门禁件或台账列**（对齐报告"不建议做的事"节）。**订正记录（CG-20261020-003，C 级夹带于 B 级批内）**＝本条原先钉的取数命令是带括号形 `grep -c '(治理)'`，与实际标题形态不符，故对本仓**恒返 0**（2026-10-20 实测：2026-10-19 起 20 条提交，带括号形命中 0；空格形 `治理` 3 条／`内容` 10 条／`发布闭环` 2 条），即 ≤30% 这条观察判据**从来没有可读的取数口**——属本仓已登记的同族形态「条文在而生效路径上没有承载」。本次只换**取数口**，不动 30% 这条判据本身，亦不据此新建门禁件（本条自述维持）。
> 5. **翻转前置**（本令何时可解除；**本条是解除条件的单源**，第 2 条的期限表述回指本条、不再自带阈值字面）＝以下两枚**合取**成就即解除，成就与否按现读客观读数判定、**不依赖发起人另设数值阈值**（授权面＝发起人 2026-10-19 面板裁定逐字「改成机器判据」；改判动因＝原字面第二枚「≥发起人所设阈值」因发起人明示「阈值另议」而不成就——仓内凭据＝本件 变更日志 CG-20261019-013 行「阈值未设故翻转前置未成就」，致本令在原文下无解除路径、只能被绕开或无限期挂起）：**① 度量可复算**＝EGPR 严格通过率与 OSC／EC 三项已有**至少两批**可复算读数（**「批」的计数载体＝本件 变更日志 变更日志中登记了该三项读数的行数**，每批一行、以 变更日志 现读为准；本条刻意不另建计数器，免成第 2 条的「新增台账列」），承担者＝A／B 输出契约校验器（现读实物＝`维护脚本/ab_contract_probe.py`），其证据注册表（`文档目录/技能价值AB_报告卡登记_20261019.json` 的 `reports[]`）**非空**、且答案内被引 `report_id` 逐枚可解析到该表；**② 技能臂胜出**＝同批同模型对照下，技能臂 EGPR 严格通过率**高于**裸模型臂，**且 ① 所要求的最少两批读数逐批同向**（无任一批反向或平局）。后半句是「显著」的**操作化**：本仓不为此另设数值阈值（设阈值即重蹈原判据「等一个裁定」的不可成就），改以**可复现的同向差**承担；其源句＝`文档目录/技能价值AB_三题两模型_试点报告_20261019.md`「只有 A 臂在 EGPR 上显著优于 B 臂，才谈得上项目优势。」（引证按件内逐字、**不钉行号**——该件现读 90 行，初稿曾把该线引作 `:100`，该行不存在）。**本条改写本身不成就 ①②、故不解除本令**：解除须由后续批按上列两枚现读判定、在 变更日志 登记并同批推本件头部链。第 1 条的北极星指标本体**不变**、仍是治理面的服务标准，本条改的只是「解除条件由谁判定」（发起人设阈值 → 现读客观读数）。**历史前置**（自 CG-20261019-017 起由上列取代，按快照纪律留此不改写）＝「北极星指标首次拿到发起人（或一位一线技术人员）签认的人类盲评读数（对应阶段 0-4）、且真实场景可用率≥发起人所设阈值；在此之前本令常驻生效」。
> 6. **边界与不重开声明**＝本令不重开已裁定「不做」行（PL-199／PL-220／PL-229／PL-242／PL-244）；不追溯已落地判据；既有判据若与本令抵触，属发起人裁定事项，走正常流程。本令**不新增常驻命中面**（不改任何校验器枚举，仅改判据文本与 变更日志 一行），与 §二 第 3 步 CG-20261018-002 已裁边界同判。

```
第 1 步：发起变更请求
  └─ 发起人填写变更请求记录（见第八节模板）
  └─ 明确变更级别（S/A/B/C）、变更内容、涉及文件

第 2 步：影响评估
  └─ 评估受影响的技能列表（见第三节影响评估清单）
  └─ 评估需回归测试的用例范围
  └─ 评估向后兼容性（是否存在破坏性变更）
  └─ 评估回滚方式和成本

第 3 步：复核审批
  └─ 先按**变更面**定承担者，再按级别定是否须复核（承担者单源＝§四 各资源专项规则的点名）：
     ├─ §四 已就该面点名复核方者 → 照其点名（本步不重述点名，避免成第二处点名）
     └─ §四 未点名复核方的面 → 默认承担者两支须**同时满足**。未点名面现行形制（示例，非闭集）＝
        接口契约措辞与参数面、程序内核行为（含红线触发逻辑的实现面）、校验器与门禁判据、
        台账源与渲染器、技能件 SKILL.md／reference.md 正文的声明与承诺面、本文件等治理件自身条款：
          (a) 常驻机算守卫＝该面既有门禁全绿（正确性闸门）。「该面」的取数＝`AGENTS.md` 验收门禁表
              所列命令中消费该被试面者，披露时须**逐枚列出实跑命令名**；该面无既有守卫覆盖时，
              须在同批披露「该面无机算承担者」，不得以复核方自述替代机算结论
          (b) 独立复核＝由未参与本批撰写的只读复核方出具（本仓现行口径＝§1.6 独立复核；
              其规范本体在合集外的《项目交付验收协议》，本件不复制其条文以免成第二源）
     └─ 一批变更同时触「已点名面」与「未点名面」时**逐面各判、两支都要满足**：已点名面的复核
        不豁免未点名面的 (a)(b)，反之亦然（防以一支自述顶替另一支）
  └─ S/A 级变更：上述承担者复核 + 变更发起人确认
  └─ B 级变更：上述承担者复核
  └─ C 级变更：无需复核，但须记录变更日志
  └─ 复核通过标准：变更内容准确、影响评估完整、回滚方案可行

第 4 步：发布与通知
  └─ 执行变更并更新受影响的所有文件
  └─ 更新变更日志（各文件自身的变更日志 + 本文件的变更日志）
  └─ S/A 级变更须在发布后 24 小时内通知所有受影响技能的维护者
```

> **第 3 步承担者取法的动因（CG-20261018-002，B 级）**：本步原三行把 S/A/B 三级的复核方一律点名 `prefab-standards-reviewer`，而该技能自述射程＝技术指标表与标准条文核验＋IC-07／IC-10 接收方，**不含契约件措辞、程序内核行为与治理条款**（现读＝该技能 `SKILL.md` 的 frontmatter `description` 与「技能定位」节）。故该条在其主要适用面上**没有可执行承担者**：批要么把该技能的门禁跑一遍当作复核通过（＝虚构达成的假绿），要么逐批登记缺口——后者已由 CG-20261018-001 的 §1.6 复核命中项 R8 实测命中第一次。第八节模板的「复核人：[prefab-standards-reviewer / 其他]」本就容「其他」，可见硬钉是疏漏而非设计。**本改只换承担者的取法，不减复核面**：该技能原覆盖的标准／条文／指标面仍由 §四 逐面点名继续覆盖，非标准面自此落到真实在场的两支。**边界**＝本改不新增常驻命中面（不据此改任何校验器枚举），故不触发「新增常驻命中面属发起人裁」。**本步无机算承担者**＝「承担者是否被真实执行」属判断层，机检只到「该面门禁全绿」为止，取态沿本仓「机检层只裁存在性、真伪归判断层」。

## 四、各共享资源的变更专项规则

### 4.1 standards-index.md（标准版本索引）

| 变更类型 | 专项规则 |
|---------|---------|
| 新增标准 | 须经 prefab-standards-reviewer 复核编号、年份、状态；须同步检查"待补充标准清单"中是否已有该条目 |
| 标准废止/替代 | 须同步更新"标准状态变更预警"章节；须在受影响技能的 reference.md 中标注替代关系；S 级（强制性国标废止）须在 24 小时内完成 |
| 标准状态变更（如现行→过渡期） | 须更新状态字段和实施日期；须通知所有引用该标准的技能 |
| 标准编号/年份修正 | B 级变更，须全文扫描确认所有引用该标准的文件均已同步修正 |

### 4.2 glossary.md（专业术语表）

| 变更类型 | 专项规则 |
|---------|---------|
| 新增术语 | 须标注来源标准，经 prefab-standards-reviewer 复核 |
| 术语定义修正 | 须记录变更原因和日期；须全文扫描确认所有引用该术语的技能输出模板无冲突 |
| 术语删除/合并 | A 级变更（可能影响已有技能的意图识别）；须评估对路由逻辑的影响 |
| 多标准定义并列 | 新增地方标准定义时，须标注推荐基准定义，不影响已有定义 |

### 4.3 interface-contracts.md（接口契约）

| 变更类型 | 专项规则 |

## 五、跨文件变更协调规则

当一次变更同时影响多个共享资源或技能文件时，须遵循以下协调规则。

**原子发布原则**：同一次变更涉及的所有文件修改须作为一个整体发布，不得分批发布导致中间状态不一致。例如，新增一条标准同时影响 standards-index.md 和某技能的 reference.md，两个文件须同步更新。

**引用方向原则**：变更沿引用方向传播。当共享资源（被引用方）发生变更时，须主动检查所有引用方是否需要同步更新。当引用方的引用内容发生变更时，须确认被引用方未发生变化。

**冲突优先原则**：当两个变更同时影响同一文件且存在冲突时，按变更级别优先级处理（S > A > B > C）；同级别变更按发起时间先后处理。

### 11.1 TTL 口径

| 类别 | TTL | 适用 |
|------|-----|------|
| 常规 | 登记日期 ＋ **90 天** | 治理类、无外部依赖、本仓内可自主处置 |
| 事件驱动 | 登记日期 ＋ **180 天** | 须用户另行授权／依赖其他遗留先闭合／外部通道不可达 |
| 限期 | 登记时明写的具体日期 | 有外部时间锚（如参照实例的腾退闸门日期） |

**到期的含义（与 §六、与核验时效台账同构）**：到期**不等于**事项失效、也**不等于**必须关闭，而是触发**须重新裁定**义务——三择一：① 处置（写处置批次号）；② 续期（改到期日并在处置批次／依据列写明续期理由）；③ 改判不做（状态改 `已裁定不做` 并写依据）。检查 7 对超期项报 **WARN 并逐条 INFO 披露，不计 `fail_count`**（沿 CG-20260917-009「不因单纯到期增加失败」口径）；结构性违法（枚举出界、编号重复、缺到期日、闭合无依据、来源 CG 不存在、登记日期晚于到期日）报 **FAIL 并计入 `fail_count`**（同机字面比对、无外部真值依赖，故首轮即 FAIL 档，与检查 6 同理）。

**状态枚举（三值，闭集）**：`待处置` / `已闭合` / `已裁定不做`。`待处置` 行到期日不得为空（填 `—` 即 FAIL）；`已闭合`／`已裁定不做` 行到期日可为 `—`，但「处置批次／依据」列**不得为空**。
