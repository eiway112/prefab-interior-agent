> **文件定位**：合集级共享资源，收录技能合集引用的全部规范标准，维护版本追踪与状态管理。路径：`shared/standards-index.md`
>
> **维护规则**：新增标准须经 prefab-standards-reviewer 复核确认编号、年份和状态；标准状态变更（如废止、替代）须同步更新本文件并通知所有引用该标准的技能。

## 一、使用说明

### 1.1 状态字段定义

本文件为每条标准维护以下状态字段，各子技能在引用标准时必须查阅本文件确认其当前状态。

| 状态字段 | 取值 | 说明 | 技能输出行为 |
|---------|------|------|------------|
| **标准状态** | `现行有效` | 标准正常实施中 | 正常引用 |
| | `即将实施` | 标准已发布但尚未到实施日期 | 引用时标注"该标准将于 YYYY-MM-DD 实施，当前设计仍以现行有效标准为准，本标准可作为前瞻性参考" |
| | `过渡期` | 新旧标准并行，过渡期内两者均可引用 | 同时列出新旧标准，标注"过渡期内新旧标准均可引用，建议优先采用新标准" |
| | `已废止` | 标准已失效，有替代标准 | 引用时标注"该标准已废止，现行替代标准为 [编号]"，并自动切换至替代标准条文 |
| | `已废止（无替代）` | 标准已失效，暂无直接替代 | 引用时标注"该标准已废止且暂无直接替代标准，建议咨询相关主管部门确认适用技术要求" |
| **被部分替代** | `被部分替代` | 标准的部分条文已被新标准替代，其余条文仍有效 | 引用被替代条文时标注"该条文已被 [新标准编号] 替代"；引用未替代条文时正常引用 |
| **官方核验日期** | `YYYY-MM-DD` | 最近一次依据可追溯的正式文本或权威公告实际核验的日期，不是文件取得日期 | 按 §1.1A 周期生成复查提醒；到期不自动改变标准效力或抹去已有核验依据 |
| **来源链接** | URL / 可定位的文本标识 | 可追溯的正式标准文本、发布或变更公告等依据，可通过本地文件、网站或知识库取得 | 按内容真实性、版本、证据所覆盖的状态或条文范围判断，不按获取渠道定级 |
| **影响条文范围** | 条文编号/范围描述 | 该标准对技能合集的核心影响条文（非穷举，仅标注关键条文） | 引用时确认所引条文在影响范围内且仍有效 |
| **核验状态** | `已官方核验` / `待核验` / `到期需复核` / `无法核验` | 记录依据确认情况与复查维护任务，不等同于标准法定状态 | 已确认依据可继续复用；单纯到期仅提醒；依据不足或明确未确认仍降级，详见 §1.1A |
| **锚定标记** | `是` / `否` | 该标准是否为标准推理引擎（SRE）的锚定基准点 | 锚定标准是推理链的坐标基准，技能文件仅需加载锚定集；非锚定标准通过推理引擎动态发现，详见 `standards-reasoning-rules.md` §二 |

### 1.1A 核验状态执行规则

| 核验状态 | 判定条件 | 技能输出行为 |
|---------|---------|-------------|
| 已官方核验 | 已依据可追溯的正式标准文本、权威发布或变更公告等，完成与结论范围相符的实际核验 | 按已核验的状态与条文范围引用，标注依据与核验日期；获取渠道不决定证据等级 |
| 待核验 | 尚未取得足以支撑所述状态或条文结论的证据，或真实性、版本、范围未确认 | 不得把未确认状态输出为确定性结论；条文级核验不自动扩为整标准状态确认 |
| 到期需复核 | 曾核验，维护周期已到或已登记复查任务；强制性国标按季度、其余标准按半年度安排（既有机器派生阈值 92／183 天，严格大于） | 有有效既有核验记录时继续复用，在输出中提示复查；到期本身不改变标准状态、适用集或证据置信度，也不代表本次已核实最新状态 |
| 无法核验 | 所需结论的依据确实不足，现有材料无法排除真实性、版本或适用范围疑点 | 不作为唯一合规判据，转人工或 IC-07 核验；仅某网站不可访问或无在线查询入口，不足以否定已有可靠依据 |

**依据与维护解耦**：SRE 从核验记录表按列名现读。无核验日期、日期不可解析或晚于当前日期，以及明确未确认的核验状态，仍触发 `inferred` 与 §1.1A 专属 `degradation`；缺记录表示依据链未确认，**不是标准已失效或已超期**。`到期需复核` 不豁免缺记录；核验状态列缺失的官方核验记录表，仍以其有效日期记录为既有核验依据。已确认记录仅因到期产生的提醒写入既有 applicability 证据，门禁报 INFO 而非 WARN。阈值仍由 `validate_governance.py` 与 `sre_reasoner.py` 分档现算，不删除到期台账、不设永久免检名单。

**效力与引用边界**：标准状态及条文替代以实际依据为准；发现废止（包括无替代废止）、部分替代、修订、勘误或证据冲突时，须按影响范围复核并更新索引，不能以「尚未发现新标准」反证永久有效。仅核对正式文本封面不能证明此后无变更。缺依据者不得作为唯一合规判据；安全、消防、隔声强制指标仍须 IC-07 条文级核验和必要的专业复核。`deterministic` 仅说明对已登记依据的确定性处理，不等于本轮重新核验最新状态或最终工程合规放行。当前没有自动联网变更监控，维护提醒不能冒充已完成复查。

### 1.2 引用规则

1. **强制性国标**（GB 55xxx 系列、GB 50xxx 系列中的强制性条文）为不可逾越的红线，任何结论不得与之矛盾。
2. **推荐性标准**和行业标准作为技术支撑，引用时须标注标准层级。
3. **图集**作为构造做法参考，不作为唯一判据。
4. **产品标准**用于验证产品是否满足基本要求，不用于推荐产品。
5. **地方标准**引用时须确认项目所在地适用性，并在输出中注明。
6. 所有引用均须标注标准编号和年份，不得省略年份。

### 1.3 标准冲突处理规则

当不同层级或同层级的标准在同一指标上存在不同要求时：

| 冲突类型 | 处理规则 | 输出标注 |
|---------|---------|---------|
| 强制性国标 vs 地方标准 | 以强制性国标为最低要求；项目所在地地方标准指标**严于**国标时，优先执行地方标准 | "项目所在地 [地名] 执行的 [地标编号] 要求 [指标值]，严于国标 [指标值]，建议按地方标准执行" |
| 强制性国标 vs 推荐性标准 | 以强制性国标为准，推荐性标准仅作补充参考 | 标注推荐性标准的更高要求，明确"强制性要求以 [国标编号] 为准" |
| 不同地方标准之间 | 根据项目所在地确定适用标准，不适用的地方标准仅作对比参考 | "项目所在地适用 [标准 A]，不适用 [标准 B]（[B 所在地]标准）" |
| 同一标准的不同版本 | 以现行有效版本为准；过渡期内新旧版本均可引用时优先推荐新版 | 标注版本差异和过渡期状态 |

## 十、标准推理引擎接口

> 本节定义本文件与标准推理引擎（SRE）的协作关系。SRE 的完整规则定义在 `shared/standards-reasoning-rules.md`。

### 10.1 本文件的角色

本文件（standards-index.md）是**版本注册中心**，维护 79 条标准的状态、版本和核验信息。SRE 在需要确认标准的时间状态（现行有效/即将实施/已废止/被部分替代）时查询本文件。

### 10.3 技能引用模式

各子技能的标准引用从"复制目录列表"转为"锚定集 + 推理引擎"模式：

```
技能文件只需包含：
1. 本技能的锚定标准子集（从 §10.2 中提取与本技能相关的锚定）
2. 指向 SRE 的引用：「本技能的标准识别与适用由合集级标准推理引擎统一管理，
   详见 shared/standards-reasoning-rules.md」
3. 版本状态查询指向本文件：「标准版本状态以 shared/standards-index.md 为准」
```

此模式消除各技能间的标准列表重复，且使技能具备动态发现未知标准的能力。

### 10.4 接口合约

| 合约 | 方向 | 功能 |
|------|------|------|
| IC-10 | 技能 → SRE | 场景查询：传入项目上下文，返回适用标准集（定义在 interface-contracts.md） |
| IC-07 | 技能 → SR | 逐条核验：传入标准编号+条文，返回版本状态和适用性（已有合约） |

**执行顺序**：IC-10 先于 IC-07。IC-10 在分析开始时确定适用标准集（面），IC-07 在输出生成时验证每条引用的版本状态（点）。
