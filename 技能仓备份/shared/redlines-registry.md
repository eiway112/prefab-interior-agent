## 一、统一编号规范

### 1.1 编号格式

```
[技能标识]-R-[优先级]-[序号]
```

| 字段 | 取值规则 | 示例 |
|------|---------|------|
| 技能标识 | 各技能的 2～3 字母缩写，在本注册表中唯一分配 | PW、OR、WS、CL |
| R | 固定字母，代表 Redline | R |
| 优先级 | P0 / P1 / P2 | P0 |
| 序号 | 该技能内该优先级红线的顺序号（从 1 开始） | 1 |

**完整编号示例**：`PW-R-P0-1`（隔墙技能 / 红线 / 安全红线第 1 条）

### 1.2 优先级层级定义

红线体系按优先级分为三个层级。当多条红线在同一场景下被触发时，高优先级红线优先执行。

| 优先级 | 层级名称 | 定义 | 触发后行为 |
|--------|---------|------|----------|
| **P0** | 安全红线 | 涉及人身安全（防火、耐火、结构安全）或路由安全（准确性、信息安全、系统可信度）的不可逾越底线 | **立即中断当前流程**，优先发出安全/路由纠正，不得继续输出其他分析结论直至问题得到明确处理 |
| **P1** | 方法论红线 | 涉及验证流程、输出规范、专业诚信、协同质量的核心约束 | 中断当前不当行为，按标准应对话术引导用户回到正确流程 |
| **P2** | 规范红线 | 涉及数据管理、引用规范、格式要求的运营约束 | 在当前输出中标注问题并修正，不中断整体流程 |

**跨技能优先级规则**：

- P0 红线在任何情况下无条件优先于 P1/P2 红线
- 当总入口的 P0 路由安全红线与子技能的 P0 安全红线同时触发时，子技能的 P0 安全红线优先（安全 > 路由）
- 总入口在整合子技能输出时，若子技能输出已触发 P0 安全标记，总入口不得"覆盖"或"忽略"这些标记

## 五、跨技能红线协同规则

### 5.1 总入口与子技能的红线层级关系

```
用户输入
  │
  ▼
总入口（OR 红线生效层：OR-R-P0-1～P1-3）
  │
  ├──→ 路由决策（OR 红线约束路由行为）
  │
  └──→ 子技能执行（子技能红线生效层：如 PW-R-P0-1～P2-5）
         │
         └──→ 子技能输出（含红线触发标记）
                │
                ▼
         总入口整合（OR 红线约束整合行为：不得覆盖子技能的 P0 标记）
```

### 5.2 跨技能红线传递规则

| 场景 | 规则 |
|------|------|
| 总入口整合子技能输出 | 总入口须检查子技能输出中是否已触发 P0 安全标记；若有，不得"覆盖"或"忽略"这些标记（OR-R-P0-5） |
| 子技能交叉路由 | 发起方技能在输出中标注的跨系统接口信息，接收方技能须尊重并按自身红线体系处理 |

#### 跨技能仲裁场景示例（2026-06-29 补充）

> **使用说明**：以下示例展示高频冲突组合的具体仲裁流程，供总入口和子技能在运行时参照。

**场景 A：用户模糊意图 + 子技能 P0 安全标记**

用户输入："我家楼板隔音不好，想做个吊顶解决。"

1. OR 识别到意图模糊（可能是楼地面问题也可能是吊顶问题）→ 触发 OR-R-P0-3（追问）
2. OR 追问："您是想改善楼上脚步声（楼板撞击声），还是想改善楼下听到的说话声（空气声）？"
3. 用户回答："脚步声。" → 路由至 FL（楼地面技能）
4. FL 执行 B2 验证，发现用户描述的构造参数不足 → 触发 FL-R-P0-5（不跳过验证），向用户追问楼板厚度和面层类型
5. 若 FL 验证过程中发现该构造的 Ln,w 可能超标 → 输出带 ⚠️ 标记的结论

仲裁要点：OR-R-P0-3 先于 FL-R-P0-5 执行（先路由后验证），两者不冲突。

**场景 B：ACE 计算精度边界 vs FL 输出精度期望**

FL 调用 ACE 计算某浮筑地面的 ΔLw：

1. ACE 收到 IC-08 请求，构造类型="浮筑地面"，弹性垫层动刚度 s=15 MN/m³，面层质量 m'=60 kg/m²
2. ACE 使用 M5 公式计算，返回 ΔLw = 22 ± 5 dB（置信度 95%）→ ACE 自身标注"专业估算（S2 数据源）"
3. FL 收到 ACE 结果，计算 Ln,w_final = Ln,w_base - ΔLw = 72 - 22 = 50 dB
4. FL 在输出中标注："撞击声压级约 50 dB（基于 ACE 专业估算，精度 ±5 dB，非实测值）"→ 满足 FL-R-P0-2（估算不冒充检测）
5. 若 50 dB 低于限值 65 dB，FL 只可输出"估算值低于 GB 55038-2025 限值 65 dB，达标与否须以现场 L'nT,w 检测报告判定"，**不得输出"✅ 满足 GB 55038-2025 要求"这类达标结论**（该措辞与本合集其余载体"本件不提供达标出口"的口径互斥，且把 ACE 估算值读成检测结论正属本场景 FL-R-P0-2 要防的那一族；本行原写「FL 给出"✅ 满足…要求"」系示例场景内的达标出口，CG-20261012-007 随 F1 同族收口）。精度说明照常保留，不因本行改判而撤

仲裁要点：ACE-R-P0-1（精度标注）和 FL-R-P0-2（估算不冒充检测）双重防护，总入口不得移除任一层标注。本场景中的「S2 数据源」属渠道／标注轴（数据分类与取证判据见 `shared/data-classification.md` §四.1）；对 B／C／D 类数据仅作信息性标注，不参与 S1-S4 渠道分级判合格（该件 §四.2），估算值的合格判据以该件 §一 C 类行（复算复现＋输入过 B 类＋适用前提写明）为准。

**场景 C：多技能同时触发 P0，输出方向矛盾**

用户输入："帮我设计一个住宅分户墙+楼板的方案，隔声和防火都要好。"

1. OR 识别为多系统协同 → 同时路由至 PW（隔墙）和 FL（楼地面）
2. PW 输出分户墙方案：Rw = 55 dB，耐火极限 2h → ✅
3. FL 输出楼板方案：发现用户描述的楼板基层厚度不确定 → 触发 FL-R-P0-5，标注"⚠️ 基层参数不足，Ln,w 结论不确定性高"
4. PW 的空气声分析和 FL 的撞击声分析同时出现在整合输出中

仲裁要点：
- FL-R-P0-1 要求：整合输出中 Rw（空气声）和 Ln,w（撞击声）必须分开展示，不得合并在同一结论句中
- 子技能 P0 安全标记优先：FL 的 ⚠️ 标记不得被 PW 的 ✅ 覆盖
- 总入口在整合输出中保留所有 P0 标记，不擅自提升确定性等级

### 18.4 ME 红线冲突仲裁规则

| 冲突场景 | 仲裁规则 |
|---------|---------|
| P0 vs P1/P2 | **P0 无条件优先**。先处理安全问题，再处理方法论或规范问题 |
| ME-R-P0-1（超越边界）vs 用户坚持要求继续 | 坚守 P0-1；可继续分析咨询范围内部分，需执业资格签章事项转介专业机构 |
| ME-R-P0-2（隐瞒不确定性）vs 用户坚持要确定结论 | 坚守 P0-2；输出降级为"仅供参考"并保留不确定性声明，不得输出确定性结论 |
| ME-R-P1-4（标准复核路由）vs ME-R-P1-1（不臆造条款号） | 两者互补：P1-4 针对路由行为（应转 SR），P1-1 针对 ME 自身输出行为（若未转 SR 则不得臆造） |
| ME-R-P1-2（伪装数据来源）vs ME-R-P1-5（咨询非检测） | 两者互补：P1-2 确保数据来源标注真实，P1-5 确保输出性质声明准确 |

### 18.5 跨技能红线协同（ME 相关）

## 二十二、新增子技能的注册流程

当新技能纳入合集中时，须按以下流程完成红线注册：

```
第1步：申请技能标识
  └─ 在本文件第二节"技能标识映射表"中分配 2～3 字母标识
  └─ 确认标识与 interface-contracts.md 中的标识一致
  └─ 确认标识不与已有标识冲突

第2步：定义红线清单
  └─ 按 P0/P1/P2 三级分层定义红线
  └─ 每条红线包含：名称、说明、触发后标准应对话术
  └─ 参考 PW 红线体系作为模板

第3步：分配全局编号
  └─ 按"[标识]-R-[优先级]-[序号]"格式分配全局编号
  └─ 在本文件中新增该技能的红线注册章节

第4步：定义冲突仲裁规则
  └─ 该技能内部红线间的冲突仲裁
  └─ 该技能红线与其他技能红线的跨技能仲裁（如有）

第5步：复核确认
  └─ 提交 prefab-standards-reviewer 复核
  └─ 确认红线编号唯一、名称无歧义、话术可执行
  └─ 更新第十九节统计摘要
```
