## 一、文件定位与使用规则

### 1.1 定位

本文件是装配式装修技能合集的接口规范文件，定义以下三类契约：

| 契约类型 | 内容 | 适用对象 |
|---------|------|---------|
| 输入参数契约 | 总入口和子技能接收任务时的标准输入格式 | 总入口（分发任务时）、所有子技能（接收任务时） |
| 输出格式契约 | 子技能完成任务后的标准输出格式 | 所有子技能（输出结论时） |
| 跨技能调用契约 | 特定技能间调用的最小参数集和返回集 | 发起方技能（传参时）、接收方技能（返回时） |

### 1.2 使用规则

1. **必传字段严格遵守**：输入参数中标注为"必传"的字段，调用方必须传递，接收方必须解析。若字段缺失，接收方应主动向调用方请求补充，不得自行假设。
2. **参数格式平台无关**：所有参数格式以纯文本/Markdown 形式定义，不依赖特定平台的 API 或数据结构，任何 AI Agent 平台均可解析。
3. **向后兼容**：接口契约中的参数格式变更须向后兼容，或通过版本号管理（如 v1.0 → v1.1），避免破坏已有技能的调用链路。
4. **数据单向流动**：子模块和补充文件向主流程提供数据，主流程的验证结论不回写子模块。
5. **引用标注**：调用方在输出中引用其他技能/文件的结果时，须标注来源（详见第六节 6.3）。

## 二、标准输入参数结构（IC-IN）

> 对应《技能合集总入口策划方案》第六节 6.3

为确保总入口与各子技能之间、以及子技能相互之间的数据传递格式统一，定义以下标准输入参数结构。所有子技能在接收任务时，应以该格式解析输入；总入口在分发任务时，应按该格式组织上下文。

### 2.1 完整参数结构

```
【任务来源】
来源类型：[总入口路由 / 子技能交叉路由 / 用户直接调用]
来源技能：[发起方技能名称，若为总入口则标注"orchestrator"]
原始用户输入摘要：[用户原始问题的简明复述，不超过100字]

【统一上下文（必传字段）】
项目类型：[住宅/公寓/酒店/医院/学校/办公/商业/其他]
空间类型：[具体空间，如：客房/分户墙/走道/卫生间等]
约束条件列表：
  - 空间约束：[墙体厚度限制、层高等，若无则标注"未提供"]
  - 功能约束：[管线分离/挂载/拆卸等需求，若无则标注"未提供"]
  - 成本约束：[目标造价区间，若无则标注"未提供"]
  - 工期约束：[施工速度要求，若无则标注"未提供"]
  - 环境约束：[潮湿/高温/洁净等，若无则标注"未提供"]
已知性能指标：[已明确的隔声/耐火/防火等指标，若无则标注"未提供"]

【上游技能分析结论（可选字段，交叉路由时必传）】
上游技能名称：[已执行的子技能名称]
上游分析结论摘要：[上游技能的核心结论]
待本技能确认的事项：[上游技能在"跨系统接口"中提出的具体问题]
已知风险/待确认事项：[上游技能标注的 ⚠️/❓ 项]

【调用请求】
期望输出类型：[专项分析 / 验证评估 / 成本分析 / 术语解释 / 其他]
优先级：[高（安全相关）/ 中（功能相关）/ 低（参考信息）]
```

### 2.2 字段传递规则

| 字段组 | 传递场景 | 规则 |
|--------|---------|------|
| 任务来源 | 所有调用场景 | 必传。来源类型决定接收方的处理逻辑（总入口路由 vs 子技能交叉路由的行为差异） |
| 统一上下文 | 所有调用场景 | 必传。若任一字段缺失（用户未提供），接收方应标注"未提供"并主动向调用方请求补充 |
| 上游技能分析结论 | 交叉路由场景 | 交叉路由时必传。总入口在启动多技能协同时，应将上游技能的分析结论按此格式传递给下游技能 |
| 调用请求 | 所有调用场景 | 必传。优先级为"高（安全相关）"时，接收方应优先处理并在输出中体现安全关注 |

### 2.3 各场景的参数适配

不同调用场景对标准输入参数的使用存在差异，以下说明各场景的适配方式：

| 调用场景 | 任务来源 | 统一上下文 | 上游分析结论 | 调用请求 |
|---------|---------|----------|-----------|---------|
| 总入口 → 单技能路由（意图类型 A） | 来源类型="总入口路由"，来源技能="orchestrator" | 总入口从用户输入中提取并组织 | 不传 | 总入口根据意图类型确定 |
| 总入口 → 多技能协同（意图类型 B） | 同上 | 总入口提取统一上下文，**对每个被调用技能传递相同的上下文** | 按协同顺序：首个技能不传，后续技能传上游结论 | 总入口根据分解后的子任务确定 |
| 子技能 → 子技能交叉路由 | 来源类型="子技能交叉路由"，来源技能=发起方名称 | 发起方将自身持有的上下文原样传递 | 发起方在"跨系统接口"中提出的具体问题 | 发起方根据问题性质确定 |
| 用户直接调用子技能 | 来源类型="用户直接调用" | 子技能从用户输入中自行提取，缺失字段主动追问 | 不传 | 用户意图即为调用请求 |

## 三、标准输出格式结构（IC-OUT）

> 对应《技能合集总入口策划方案》第六节 6.1

为便于总入口整合多技能输出，各子技能的输出应遵循统一的元数据结构。

### 3.1 完整输出结构

```
【技能标识】
技能名称：[子技能名称]
技能角色：[专项/跨系统/通用/质量工具]

【分析结论】
[子技能的核心输出内容]

【确定性标记】
- ✅ 已确认：[列出]
- ❓ 需确认：[列出]
- ⚠️ 风险提示：[列出]
- ❌ 不满足/不适用：[列出]
- 🔲 无法判断：[列出]

【跨系统接口】
- 与[相邻系统]的接口条件：[描述]
- 需要[其他技能]确认的事项：[描述]

【标准引用】
- [引用的标准编号和条款]

[标准免责提示]
```

### 3.2 确定性标记使用规范

| 标记 | 含义 | 使用条件 | 总入口整合时的处理 |
|------|------|---------|-----------------|
| ✅ | 已确认 | 有充分证据（检测报告/标准条文明确支持） | 直接纳入整合输出 |
| ❓ | 需确认 | 基于专业估算或推断，需检测报告或其他信息确认 | 保留标记，不升级为 ✅ |
| ⚠️ | 风险提示 | 存在潜在风险或不确定因素 | 在整合输出的风险提示中体现 |
| ❌ | 不满足/不适用 | 明确不满足要求或不适用于当前场景 | 直接纳入整合输出 |
| 🔲 | 无法判断 | 关键信息缺失，无法给出有效判断 | 在整合输出中标注为待补充项 |

### 3.3 跨系统接口的触发与传递

当子技能在执行过程中发现用户问题涉及相邻系统时，应在输出的【跨系统接口】部分标注，由总入口决定是否启动协同流程。

**触发规则**：

| 发起技能 | 触发条件 | 目标技能 |
|---------|---------|---------|
| 隔墙技能（PW） | 用户询问墙面饰面与隔墙基层的适配 | 墙面技能（WS） |
| 墙面技能（WS） | 用户询问墙面饰面对隔墙结构的要求 | 隔墙技能（PW） |
| 吊顶技能（CL） | 用户询问吊顶与隔墙/墙面的收口 | 隔墙/墙面技能（PW/WS） |
| 楼地面技能（FL） | 用户询问地面与湿区防水的接口 | 厨卫技能（BK） |
| 收纳技能（ST） | 用户询问入墙式收纳对隔墙的要求 | 隔墙技能（PW） |
| 任何专项技能 | 用户询问标准条文的有效性或合规性 | 标准复核工具（SR） |
| 任何专项技能 | 用户问题超出该技能的专业边界 | 通用专家（ME）——通用兜底 |

**降级策略**：当 ACE 调用失败时，吊顶技能输出标注"简化估算（隔声计算引擎暂不可用）"，只输出定性贡献机制说明 + 建议实验室检测；PL-229 暂停期（v1.14.0 起）不输出任何数值（含 reference.md A1.2 的 v1 经验区间 5-15 dB〔S3〕）〔IT-2 原形制见 CG-20260808-023〕。ACE 可达而返回 PL-229 降级（`原因代码`＝`PL-229`）不属调用失败，不得据此改走本降级路径（§6.2）。

### 4.5 多技能协同场景的参数传递（八步法）

> 对应《技能合集总入口策划方案》第四节 2.3 多技能协同规则（八步法，含第0步标准推理）

当总入口启动多技能协同时，各步骤的参数传递遵循以下规范：

```
第0步：标准推理（新增）
  总入口提取项目上下文（项目类型、空间类型、所在地、构造体系、性能需求）
  调用 IC-10（标准推理引擎），获取本场景的适用标准集
  输出：适用标准集（含层级、权限、角色）+ 推理路径
  关键：后续所有子技能的分析均以此标准集为合规基准

第1步：任务分解
  总入口分析用户问题 → 识别涉及的部品系统 → 确定需要调用的子技能列表
  结合第0步的适用标准集，明确各技能须在哪些标准约束下执行
  输出：[技能A, 技能B, ...] + 各技能的子任务描述 + 适用标准集

第2步：上下文建立
  总入口提取统一上下文（IC-IN 必传字段）
  对每个被调用的子技能传递【相同的统一上下文】+【适用标准集】
  关键：确保所有子技能基于相同的项目类型、空间类型、约束条件和标准基准进行分析

第3步：专项分析（并行）
  各专项技能按各自的 IC 契约独立执行
  各技能在适用标准集约束下进行分析，引用标准时须使用标准集中的版本
  各技能独立输出标准输出格式（IC-OUT）

第4步：版本一致性校验
  总入口检查各子技能输出中【标准引用】部分：
  - 同一标准是否被不同技能引用了不同版本
  - 各技能引用的标准是否均在适用标准集内（未超出第0步确定的范围）
  - 各技能引用的标准状态是否均为"现行有效"（参考 shared/standards-index.md）
  - 评价量是否一致（如 Rw+C vs DnT,w+C）
  如发现不一致：标注冲突 → 以效力层级更高的标准为准 → 提示用户确认
  如需复核：调用 IC-07（标准复核工具）

第5步：跨系统审查
  调用 prefab-mep-integration-system，传递：
  - 各专项技能的分析结论
  - 审查要求：管线分离策略一致性、接口冲突检测、安装顺序合理性

第6步：标准复核（如适用）
  调用 IC-07（标准复核工具），对高风险标准引用执行复核

第7步：整合输出
  总入口汇总各技能输出 → 识别冲突和待确认事项 → 整合为统一回复
  冲突处理规则：标注冲突点 → 分析原因 → 建议用户确认 → 不做"仲裁"
  如用户需要：调用 prefab-acceptance-checklist-generator 生成验收清单
```
