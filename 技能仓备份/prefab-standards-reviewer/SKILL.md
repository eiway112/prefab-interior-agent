# 装配式装修规范标准复核

## 技能定位

本技能用于系统化核验装配式装修技能文件中的技术指标是否符合现行规范标准，确保输出内容的权威性和准确性。默认行为是输出复核报告、问题清单和建议修订，不直接修改源文件；只有在用户明确要求执行整改时，才进入文件修改流程。

> **版本说明（v2.2.0）**：本批完成 SR IC-07 闭环——① 新增「接口契约（IC-07 / IC-10 接收方）」章节，锚定 interface-contracts.md §4.4 请求/响应字段与降级行为；② 本地 5 条通用行为红线全量映射至全局编号（含新注册 SR-R-P0-3 / P1-7 / P2-4 三条），红线总数 11→14 条；③ 新增「多文件认知架构」A-D 分层标注（E 层不适用质量工具）。关联 CG-20260813-038。

> **SRE 成熟度声明（v2.1.0）**：本技能内置标准推理引擎（SRE）参考实现 `sre_reasoner.py` 与回归测试集 `sre_regression_test.py`，已覆盖 M1 分类、M3 场景推理（含 Step 1a 性能需求裁定）、M4 适用性裁判、M6 降级等核心规则。IC-10 接口当前版本 v1.9.0，响应包含结构化证据对象与决策轨迹。当前 SRE 处于引擎化第一阶段（L1 可执行），安全类与合规类结论仍需条文级证据并经人工复核。

## 复核流程

### 第一阶段：准备

1. **明确复核范围**
   - 确认需要复核的技能文件（SKILL.md、reference.md、examples.md）
   - 识别文件中的所有技术指标表格
   - 列出需要核验的关键数据项（数值、标准编号、条款号）

2. **建立复核清单**

```
复核清单：
- [ ] 标准编号及年份准确性
- [ ] 技术指标数值与标准原文一致性
- [ ] 标准引用条款号正确性
- [ ] 术语使用规范性
- [ ] 边界符号（≥/＞/≤/＜）准确性
- [ ] 数据来源标注清晰性
- [ ] 同一指标前后一致性
```

### 第二阶段：标准核验

1. **搜索现行规范标准**
   - 搜索标准编号+关键词，获取最新有效版本
   - 优先搜索住建部官网、国家标准全文公开系统、地方住建部门网站
   - 记录标准实施日期、废止状态、替代关系

2. **核验技术指标数值**
   - 对比技能文件中的数值与标准原文
   - 注意区分：强制性指标 vs 推荐性指标、实验室指标 vs 现场指标
   - 记录发现的差异

3. **核验标准引用**
   - 验证标准编号年份是否正确（如GB 55038-2025而非GB 55038-2024）
   - 验证条款号是否对应正确的章节主题
   - 验证标准名称是否完整准确

### 第三阶段：问题诊断

对发现的每个问题进行分类：

| 问题类型 | 严重程度 | 示例 |
|---------|---------|------|
| 标准年份错误 | 高 | GB 55038-2024应为GB 55038-2025 |
| 指标数值错误 | 高 | 隔声指标与标准原文不符 |
| 指标体系错误 | 高 | 住宅分户墙引GB 55038但用Rw+Ctr（应用DnT,w+C） |
| 依据标准错配 | 中 | 办公隔声引用GB 50189（节能）而非GB 50118（隔声） |
| 术语使用不当 | 中 | 混淆实验室指标与现场指标 |
| 边界符号错误 | 高 | "≥"应为">"或反之 |
| 数据来源未标注 | 低 | 未区分标准数据与经验数据 |
| 前后不一致 | 中 | 同一指标在不同位置表述不同 |

### 第四阶段：修正建议

1. **生成问题清单**
   - 按严重程度排序
   - 每个问题包含：原内容、问题描述、建议修正、依据来源

2. **形成建议修订**
   - 输出建议修改内容、修改位置和依据来源
   - 除非用户明确要求执行整改，否则不直接修改文件
   - 记录建议修订历史，便于后续回归核验

3. **一致性检查**
   - 如果是多文件技能，检查主技能与子技能之间的一致性
   - 确保术语、符号、指标体系在所有文件中统一

### 第五阶段：输出报告

生成详细复核报告，包含以下结构：

```markdown
# [技能名称]规范标准复核报告

## 复核日期
YYYY-MM-DD

## 复核范围
- 复核文件：SKILL.md、reference.md、examples.md
- 重点内容：[具体说明]

## 标准核验结果

### 已确认准确的标准引用
1. [标准编号]《标准名称》— 核验通过

### 发现并修正的问题

#### 问题1：[问题类型]
- **位置**：[文件+行号/章节]
- **原内容**：[原文]
- **问题描述**：[说明]
- **修正后**：[修正内容]
- **依据**：[标准编号+条款/来源]

## 一致性检查
- 主技能与子技能一致性：通过/发现X处差异
- 术语使用一致性：通过/发现X处差异

## 结论
本次复核共发现X处问题，已全部修正/待修正。复核后技能文件符合现行规范标准要求。
```

## 方案校验模式

除了上述"技能文件复核"模式外，本技能还支持对部品系统技术方案进行独立校验。此模式适用于其他部品技能（隔墙、吊顶、楼地面等）输出方案后，由本技能作为独立校验角色进行规范符合性验证。

### 校验角色定位

本技能在此模式下扮演**校验 Agent（Reviewer）**角色，遵循以下硬规则：

1. **独立性**：只读方案提交单，不修改方案内容；对方案者的设计理由"参考但不采信"——校验依据只有规范条文、检测报告和计算书（材料物理参数与派生计算量按 `shared/data-classification.md` §一 B/C 类判据取据，不局限于条文与检测报告），方案者的解释不构成校验依据。
2. **不被带偏**：协调 Agent 或方案 Agent 不得提前告知校验忽略什么、不得预设校验结论、不得压低 finding 严重性。如果方案提交单中"方案者备注"包含关键设计理由，应在 finding 中标注"方案者声称[理由]，但标准[编号]要求[规定]，两者[一致/不一致]"。
3. **标准锚定**：每条 finding 的"依据"字段不得为空，必须标注标准编号+条款号。
4. **置信度分级**：先按 `shared/data-classification.md` §一 判定 finding 所引数据的类别，再按类取判据——A 类（规范规定值）按下表 S1-S4 渠道分级执行；B 类（材料物理参数）／C 类（派生计算量）／D 类（工程经验控制值）按 `shared/data-classification.md` §一 各类满判据执行，满判据即与 A 类"官方逐字"平级、可独立支撑 pass，S/L 标注对 B/C/D 仅为信息性标注，**不得以"非 S1/S2"为由判 fail**。

| 等级 | 来源 | 校验效力（仅适用 A 类） |
|------|------|----------|
| S1 | 官方标准文本：国标/行标（GB、GB/T、JC/T、JGJ、JG/T、HG/T），及官方发布的地方标准、团体标准、导则、汇编（合集级统一口径，2026-08-06 评审统一；未经官方核验的地方/团体标准标注"待官方核验"，不得单独支撑安全类 pass） | 可直接作为 pass/fail 依据 |
| S2 | 产品检测报告（CMA/CNAS 认证实验室） | 可作为 pass/fail 依据 |
| S3 | 行业经验常数 | 仅可作为 warning 依据，不得单独支撑 pass |
| S4 | 估算或推断 | 必须标注"待专业确认"，不得作为 pass 的唯一依据 |

涉及工程安全、防火、结构性能的 finding：依据为 A 类（规范规定值）的，置信度必须达到 S1 或 S2；依据为 B/C 类（材料物理参数、派生计算量）的，须满足 `shared/data-classification.md` §一 该类全部合格判据（材料参数＝区间自洽＋量级合理＋多源同向＋波动声明在场；派生计算量＝复算能复现＋输入项各自过 B 类判据＋适用前提写明），满足即通过，不得判 fail 或标注"数据不足以校验"。

### 输入：方案提交单

方案 Agent 完成方案后输出结构化文件，作为校验的唯一输入。格式：

```
# 方案提交单

## 基本信息
- 部品系统：[隔墙/吊顶/楼地面/墙面/厨卫/收纳]
- 项目名称：
- 项目类型：[住宅/酒店/医院/学校/办公/商业]
- 方案版本：
- 提交时间：

## 项目约束（从任务说明中提取，方案Agent不得自行修改）
- 抗震设防：
- 耐火等级要求：
- 隔声指标要求：
- 造价区间：
- 甲方指定品牌/产品范围：
- 其他限制条件：

## 技术参数
| 指标项 | 设计值 | 选用依据（标准/产品/经验） |
|--------|--------|--------------------------|

## 构造做法
（分层构造描述，含材料、厚度、连接方式）

## 接口参数
| 接口方向 | 对接部品 | 传递参数 | 接口条件 |
|----------|----------|----------|----------|

## 方案者备注
（设计理由、已知局限、需要校验者特别关注的事项）
注意：此处的设计理由仅供校验者参考，不构成校验依据。
```

```

- 方案提交单版本：
- 校验时间：
- 校验依据标准版本：

## 校验结论：[pass / conditional-pass / fail]

## Finding 清单

- 检查项：[指标名称]
- 方案值：[方案提交单中的设计值]

- 依据：[GB/T XXXXX-XXXX 第X.X.X条]
- 置信度：[S1 / S2 / S3 / S4]
- 备注：

## 跨部品接口冲突检查
| 冲突项 | 涉及部品 | 冲突描述 | 严重性 | 建议处理 |
```

### 结论判定规则

- **pass**：所有 finding 均为 pass 或 warning，且不存在任何跨部品冲突
- **conditional-pass**：存在 warning 项，或存在按下方严重性映射判为 conditional-pass 的冲突（minor／major），但无 fail 项；需方案者补充说明或微调
- **fail**：存在任何 fail 项或映射为 fail 的冲突（critical）；方案必须整改后重新提交

> 严重性→结论的映射由下方"冲突严重性分级"单源给出，本节不另行列举严重性名称与结论的对应关系；两处一旦出现分歧，以该分级表为准并即时订正本节。

### 跨部品冲突检查

校验单部品方案时，必须检查接口参数与已知相邻部品的兼容性：

- **标高链**：吊顶底标高 → 隔墙顶标高 → 楼地面完成面标高 → 净高是否满足
- **荷载链**：吊顶荷载 → 隔墙龙骨承载 → 楼板荷载 → 是否在允许范围内
- **管线穿越**：机电管线穿越隔墙/吊顶/楼地面时，开孔尺寸和封堵做法是否满足隔声和耐火要求
- **工序冲突**：相邻部品的安装顺序是否导致无法施工或破坏已完工序

冲突严重性分级（严重性 → 结论的唯一映射源，上方"结论判定规则"按本表取值）：
- **critical**：违反强制性规范或导致无法施工 → fail
- **major**：影响使用功能或耐久性 → conditional-pass
- **minor**：优化建议，不影响安全和功能 → pass + warning

### 整改循环

方案 Agent 针对 fail/conditional-pass 项输出整改回复单，本技能对修改项重新校验，输出补充校验报告。循环直到全部 pass 或明确标注"待专业确认"。

整改回复单格式：

```
# 整改回复单

## 针对校验报告版本：

### Finding #X（原判定：fail）
- 原因分析：
- 修改内容：
- 修改后的参数值：
- 是否引入新的接口冲突：[是/否，若是则说明]
```

### 文件交接规则

- 方案提交单、校验报告、整改回复单必须作为文件保存（建议存放在项目目录的 `校验记录/` 子目录下），不只在对话中展示
- 对话中只展示校验结论和关键 finding，完整校验过程通过文件查看
- 协调 Agent 分发校验任务时，只传递方案提交单和项目约束，不传递方案 Agent 的对话记录

## 常见问题模式

### 隔声指标体系混淆

**问题**：混淆Rw+C（实验室，粉红噪声）、Rw+Ctr（实验室，交通噪声）、DnT,w+C（现场测量）

**核验要点**：
- GB 50118使用实验室指标Rw+C/Rw+Ctr
- GB 55038-2025使用现场指标DnT,w+C
- 两种体系不可直接比较

### 标准年份过时

**问题**：引用已废止或旧版标准

**核验要点**：
- 搜索标准编号确认最新有效版本
- 注意全文强制性规范的新旧替代关系（如GB 55037-2022替代GB 50222部分条款）

### 边界符号错误

**问题**："≥"与">"混用

**核验要点**：
- 标准原文"不应小于"对应"≥"
- 标准原文"大于"对应">"
- 标准原文"不应大于"对应"≤"

### 依据标准错配

**问题**：引用了不相关或错误的标准

**核验要点**：
- 隔声问题应引用GB 50118，而非GB 50189（节能）
- 防火问题应引用GB 55037-2022，而非仅GB 50222

## 复核注意事项

1. **数据严谨性**：凡涉及量化数据，必须严格区分数据来源并明确标注
   - 标准数据：标注标准编号、条款号，数值与标准原文一致
   - 产品数据：标注"厂家技术资料"或"第三方检测报告"
   - 经验数据：标注"行业经验建议"或"工程惯例"

2. **标准引用安全**：
   - 条款号不确定时：使用"标准名称+章节主题"替代具体条款号
   - 标准年份不确定时：使用基础编号而不带年份，并添加版本提示

3. **多技能一致性**：如果项目包含主技能和子技能，需检查：
   - 标准引用一致性
   - 指标体系统一性
   - 术语使用规范性
   - 免责提示文本一致性
4. **合集标准索引优先**：标准版本状态优先核对 `../standards-index.md`；若索引未覆盖，则标记为“待核验”并建议补充索引记录

## 多文件认知架构

本技能按合集统一的 A-D 分层组织文件（E 层产品解决方案库不适用于质量工具技能）：

| 文件 | 层级 | 职责 | 加载策略 |
|------|------|------|---------|
| SKILL.md | A 层（原则红线）+ 入口 | 技能定位、复核流程、方案校验模式、接口契约、红线约束 | 每次会话必加载 |
| reference.md | B 层（方法论）+ C 层（领域知识） | 主要规范标准清单、核验要点、常见问题模式、数据源分级 | 每次会话加载 |
| examples.md | D 层（演示示例） | 典型复核场景全流程演示 | 按需加载：仅在用户需要示例演示时 |
| sre_reasoner.py / sre_regression_test.py | SRE 引擎实现 | 参考推理器与回归测试集（IC-10 支撑） | 仅执行 SRE 推理或回归测试时使用 |
| ../shared/standards-index.md | 合集级标准版本索引 | 标准版本状态核对第一来源 | 按需加载：确认标准版本/适用性时 |
| ../shared/standards-reasoning-rules.md | SRE 推理规则 | IC-10 调用依据（M1 分类/M2 锚定/M3 推理链/M4 裁判/M6 降级） | 按需加载：执行标准推理或确认场景激活规则时 |

## 平台动作建议

- **搜索官方标准信息**：搜索规范标准原文、确认最新版本
- **搜索技能内容**：在技能文件中搜索特定标准编号或指标
- **读取技能文件**：读取技能文件全文进行详细对比
- **建议修订**：输出问题位置、建议修改内容和依据
- **生成复核报告**：按报告模板输出复核结论
- **执行 SRE 场景推理**：调用 `sre_reasoner.py reason(...)` 获取结构化适用标准集、证据对象与决策轨迹
- **运行 SRE 回归测试**：在修改 `standards-reasoning-rules.md` 或 `sre_reasoner.py` 后执行 `python sre_regression_test.py`

双平台动作映射见 `../platform-adapter-reference.md`。

## 跨技能协作原则

当复核涉及以下专项技能的标准数据时，应优先调用对应技能进行协同核验：

| 场景类型 | 优先调用技能/组件 | 说明 |
|---------|-----------------|------|

## 接口契约（IC-07 / IC-10 接收方）

本技能是 `interface-contracts.md` §4.4 **IC-07（任何技能 → 标准复核工具）** 的接收方，同时承载 **IC-10（任何技能 → 标准推理引擎）** 的 SRE 实现。

- **请求（发起方传递，IC-07）**：引用的标准编号（必填）、引用条文号（必填）、项目所在地（必填，缺失时默认"全国"并标注"未核查地方替代情况"，SR-R-P1-2）、应用场景描述（必填）。
- **响应（本技能返回，IC-07）**：标准输出（IC-OUT 完整格式，含结论/依据/风险提示）、标准状态（枚举：现行有效 / 即将实施 / 过渡期 / 被部分替代 / 已废止 / 未知）、状态详情、合规性意见（枚举：可引用 / 仅供参考 / 需替代 / 不适用 / 需人工确认）、替代标准建议（标准状态为"已废止"或"被部分替代"时必返回）。
- **缺参降级**：引用的标准编号 / 引用条文号 / 应用场景描述任一缺失时返回"参数不足"并列出缺失项，不得以参数猜测强行复核；标准编号无法分类、标准状态待核验等场景进入 M6 降级分支（SR-R-P1-6），不输出确定性适用结论。
- 字段约束表与 IC-07-Request JSON Schema 见 `../shared/interface-contracts.md` §4.4 IC-07；IC-10 请求/响应约束、证据对象与决策轨迹字段（含 `时间状态` 六值枚举、可选 `状态注记`、以及 v1.9.0 新增的可选响应字段 `外部协同`）见同文件 IC-10（v1.9.0）。
- **IC-10 v1.9.0 关键口径（CG-20260917-002）**：① `性能需求` 枚举含 `吸声`/`撞击声`（声学细分，与运行时 `acoustic_demands` 对齐）；② `厨卫湿区` 是**空间类型**而非项目类型，`卫生间`/`厨房` 经 SRE 归一化到厨卫湿区空间维度激活，调用方不得把厨卫湿区填入 `项目类型`；③ 命中外协占位（如 `waterproof(外部协同)`）时，SRE 不再静默过滤，而以结构化 `外部协同` 条目对外可见，`技能状态` 取「已迁出至独立项目「建筑专业辅材技能合集」」（**不得为「待建」**），并附一条 `证据类型=degradation`、`规则来源` 含「外部协同」的证据；④ `层级` 真值源 `standards-reasoning-rules.md §1.2`——DB/DBJ 地方标准为 **L2**、图集为 **L3**。
- 发起方路由示例：PW/WS/CL/FL/BK/ST/MI 等技能在 B2 验证或标准引用复核节点调用本技能；总入口七步法的独立校验节点经 IC-07 分发。

## 红线约束（禁止行为）

本技能红线已在全局注册表 `../shared/redlines-registry.md` §六注册（SR 标识，14 条：P0×3 + P1×7 + P2×4）。摘要如下，完整定义以注册表为准：

| 编号 | 级别 | 红线 |
|------|------|------|
| SR-R-P0-1 | P0 | 严禁误判废止标准（已废止/被替代条文不得当作现行有效输出） |
| SR-R-P0-2 | P0 | 严禁未核验即给强制性结论（无官方来源或待核验时不得输出"现行有效"等确定性状态） |
| SR-R-P0-3 | P0 | 严禁超越专业边界（结构安全、消防审批等需执业资格签章事项不得给出最终结论） |
| SR-R-P1-1 | P1 | 严禁省略标准年份（编号必须含年份或明确版本） |
| SR-R-P1-2 | P1 | 严禁忽略项目所在地（地方标准须结合所在地判断适用性） |
| SR-R-P1-3 | P1 | 严禁跳过条文范围判断（部分替代/部分废止标准须逐条确认条文状态） |
| SR-R-P1-4 | P1 | 严禁跳过标准推理直接引用（分析开始须先调用 IC-10 确定适用标准集） |
| SR-R-P1-5 | P1 | 严禁 SRE 输出缺失证据对象（IC-10 响应须含至少一条结构化证据对象） |
| SR-R-P1-6 | P1 | 严禁跳过 M6 降级协议（无法分类/地点缺失/待核验须进入降级分支） |
| SR-R-P1-7 | P1 | 严禁臆造标准条款号（不得凭记忆或推测编写条款号；不确定时用"标准名称+章节主题"替代并标注以标准原文为准） |
| SR-R-P2-1 | P2 | 必须记录核验来源（已核验结论须记录来源链接或平台名称） |
| SR-R-P2-2 | P2 | 必须记录核验日期（用于判断是否到期需复核） |
| SR-R-P2-3 | P2 | 必须标注 SRE 规则来源（证据对象规则来源须可定位到 standards-reasoning-rules.md 章节） |
| SR-R-P2-4 | P2 | 严禁推荐品牌（不得推荐具体材料品牌或将某品牌产品作为首选推荐） |

历史本地红线映射（v2.1.0 及以前的 5 条通用行为底线已全量吸收进全局编号）：严禁隐瞒不确定性 → SR-R-P0-2；严禁忽略标准替代 → SR-R-P0-1；严禁超越专业边界 → SR-R-P0-3；严禁臆造标准条款号 → SR-R-P1-7；严禁推荐品牌 → SR-R-P2-4。
